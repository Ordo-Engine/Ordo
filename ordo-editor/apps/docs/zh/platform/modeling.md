# 事实、概念与契约

它们描述一个项目的规则读什么、返回什么，Studio 在编辑规则和测试时会用到。在命令行项目里，它们是 `facts.json`、`concepts.json` 和 `contracts/<name>.json`。

## 事实

事实是从外部传进来的输入字段，比如 `user.age`、`order.amount`。

| 字段          | 含义                                         |
| ------------- | -------------------------------------------- |
| `name`        | 规则里用的字段路径                           |
| `data_type`   | `string`、`number`、`boolean`、`date` 或 `object` |
| `source`      | 值从哪里来，给看目录的人参考                 |
| `null_policy` | `error`、`default` 或 `skip`                  |
| `description`、`owner` | 说明文字                            |

调用方在执行请求的 `input` 里传入事实。没传的事实按缺失处理，不算错误。

## 概念

概念是由事实算出来的命名值，比如由 `user.age >= 18` 得到的 `is_adult`。它有 `name`、`data_type`、`expression`，以及它依赖的 `dependencies`。概念在规则执行前算好，命令行和平台的算法一样，所以本地 `ordo test` 的结果和线上一致。

## 契约

决策契约针对一个规则集，说明它需要哪些输入字段、返回哪些输出字段，每个字段有类型和是否必填。另外还记录负责人、版本范围、可选的 p99 延迟目标和备注。用它和调用方约定好进什么、出什么。

## 子规则

子规则是几个规则集共用的一段逻辑，比如 KYC 校验或风险打分。它可以属于一个项目，也可以属于组织，让多个项目一起用。规则集用子规则步骤调用它，把输入传进去，再把输出映射回来（见[规则结构](/zh/guide/rule-structure#sub-rule)）。

规则集发布时，平台会把它用到的每个子规则的当前版本复制进去，最多 8 层。之后再改子规则，不会影响已经发布的规则集。要用上新逻辑，就重新发布这些规则集。
