# 性能测试

2026-03-11 在 Apple M1 Pro（10 核，16 GB，macOS）上测得。引擎数据用 Criterion.rs；HTTP 数据用 `hey`，每轮 10 秒，服务以 release 模式运行，`--log-level error`。测试规则是一个有四个分支的决策（`score >= 90 / 70 / 50 / default`），输入是 `{"score": 75}`。

换了硬件和规则，结果会不同。可以自己用 `cargo bench -p ordo-core` 跑。

## 引擎

| 测试项 | 耗时 |
| --- | --- |
| 两个步骤的规则（决策、终止） | ~361 ns |
| 四个分支的规则 | ~573 ns |
| 同一规则，编译后的 `.ordo` 二进制 | ~553 ns |
| 一次比较，`age > 18` | ~40 ns |
| `age > 18 && status == "active"` | ~80 ns |
| `score * 0.6 + bonus * 0.4` | ~67 ns |
| JIT 后的数值表达式 | ~8 ns |
| 解析一个表达式（加载时一次） | 1 到 2 µs |
| 1000 条的批量执行 | 每秒约 270 万次 |

同一台机器上，同样的四分支规则在其他 Rust 引擎里：

| 引擎 | 每次耗时 |
| --- | --- |
| Ordo（字节码 VM） | 573 ns |
| Rhai（AST 解释器） | 728 ns |
| Zen Engine / GoRules | 4,200 ns |
| 纯 Rust `if/else`，作参照 | 3.5 ns |

## HTTP 服务

单实例，`POST /api/v1/execute/:name`：

| 并发 | 每秒请求 | p50 | p99 |
| --- | --- | --- | --- |
| 1 | 14,634 | 0.06 ms | 0.10 ms |
| 10 | 47,960 | 0.19 ms | 0.40 ms |
| 50 | 59,440 | 0.76 ms | 2.90 ms |
| 200 | 62,511 | 2.78 ms | 9.90 ms |
| 500 | 60,577 | 6.60 ms | 29.2 ms |

吞吐在每秒 6 万请求左右持平。内存空闲时 24.6 MB，200 并发时 46.2 MB。

批量执行，50 并发：

| 每个请求的输入数 | 每秒请求 | 每秒执行规则 |
| --- | --- | --- |
| 10 | 53,018 | 530,180 |
| 100 | 22,049 | 2,204,900 |
| 500 | 6,128 | 3,064,000 |

通过 NATS 同步的一写一读两个实例，每个的处理能力和单实例差不多。在同一台机器上，两者合计达到每秒 83,082 请求。

通过 HTTP 调用的其他引擎，50 并发：

| 引擎 | 每秒请求 | p99 |
| --- | --- | --- |
| Go `net/http`，逻辑写死，作参照 | 70,134 | 2.30 ms |
| Ordo | 58,374 | 3.40 ms |
| OPA（Go） | 30,398 | 8.50 ms |
| json-rules-engine（Node.js） | 17,205 | 6.10 ms |
| Grule（Go） | 6,547 | 16.2 ms |

通过 HTTP 时，每个请求的大部分时间花在 HTTP 层，而不是规则上。Ordo 每个请求也比裸处理函数多做一些事：查找规则、检查租户和角色、审计采样和计时。
